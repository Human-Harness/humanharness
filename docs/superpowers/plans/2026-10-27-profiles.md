# Profiles Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A harness may declare `profiles`: several people use one install, each with their own folder inside the app's folder. A profile's folder holds that person's scopes, notes, data, material, chats, settings, setup steps, usage and AGENTS.md, and it is the engine's working folder while the profile is active. Each profile has its own history. The engine, its sign-in, the model tiers, the language, the appearance, the folder's place and its backup stay app-wide. The person adds a profile (a name and a few fields from the harness's `profile` collection), switches between profiles from Home or the work screen's top bar, archives one or moves one to the Trash. A switch closes the open task first, like a scope switch. Settings › Usage adds up every profile and can show each person. Moving the folder moves every profile's history. A harness that declares no `profiles` works exactly as today (D0 below).

**Architecture:**
- **Contract (harness-sdk).** New `profiles.ts`: `PROFILE_COLLECTION` (`"profile"`), `PROFILE_COLORS`, `profilesSchema` (`label`, `fields`), `hasProfiles`, `profileFormSpec` (the `InputSpec` of the add/edit form). `index.ts`: the manifest's optional `profiles` and its rules in the `superRefine` (a `profile` collection that is `single`, not scoped, with a `name` string; `fields` starts with `name`, names only fields of it the core form can draw).
- **Registry (workspace).** `layout.ts`: `profilesFile(root)` → `<root>/.harness/profiles.json`. New `profiles.ts`: `PROFILE_ID`, `isProfileId`, `cleanProfileTitle`, `profileSlug`, `profileDir`, `ProfileStore` (atomic writes, one at a time; a broken file set aside).
- **Where things live (shell main).**
  - `ui/src/client.ts` `AppConfig.profile`: the active profile. `config.ts` `ConfigStore` keeps it (the window can never set it) and gains `setProfile`.
  - New `profile-base.ts`: `baseFor(config, profiles)` (the root without profiles; `<root>/<profile>` with them; null while none is active), `profileOfBase`, `isInsideFolder`.
  - `index.ts`: `baseOf` uses `baseFor` and never answers the root of a profiles app; `validConfig` is null until a profile is active; the runtime, its history, the standalone history, the chat log and `hh:openPath`/`hh:revealPath` all use the base.
- **Switching (shell main).** New `profile-switch.ts`: `ProfileSwitch` (refused while quitting, a task operation, a turn, a restore, a move or an engine change runs; holds all of them off while it runs). New `profiles.ts`: the `Profiles` controller (state, create, open, archive, delete to the Trash, the registry's copy of the name and colour).
- **Wiring.** `index.ts`: `AppState.profiles`, the `hh:profile*` handlers and the `hh:profiles` channel; what happens on arrival in a profile. The preload and the client: `client.profiles`. `SetupStepProps.profile`.
- **Shared views (shell main).** `usage-log.ts`: `mergeUsage`, `profilesUsage` (Settings › Usage sums every profile; `UsageSummary.profiles`). `engine-switch.ts`: `archiveChatsOnEngineChange` (every profile's chat). `move-folder.ts`: `MoveDeps.subfolders`, one history per profile moved and rolled back together, `recoverMove` reads `histories` from the journal.
- **The window (ui).** New `profiles.ts` (`AVATAR_COLORS`), `ProfileSwitcher.tsx` (`Avatar`, `ProfileSwitcher`) on Home and in the work screen's top bar; `ProfileStep.tsx`, a core step of the setup screen (the first profile, and every "Add"); `ProfilesSection.tsx` in Settings › General (edit the active one, archive, delete twice); "Usage by person" in Settings › Usage.
- **Fixture.** `packages/fake-agent/fixtures/profiles-harness` (id `family`) drives the unit and end-to-end tests.

**Tech Stack:**
- Unchanged: TypeScript, pnpm via corepack, Electron 44 + electron-vite 5, React 19, i18next, zod 4, isomorphic-git, Vitest + happy-dom, and Playwright with the fake agents.
- No new dependency.

Spec: `docs/superpowers/specs/2026-10-25-profiles-design.md` (source of truth; "§" and "D" numbers below refer to it). It builds on plans 1–6 (`2026-10-25-scopes-and-data.md`, `2026-10-25-input-blocks.md`, `2026-10-26-harness-settings.md`, `2026-10-26-task-modes.md`, `2026-10-26-task-phases.md`, `2026-10-27-harness-setup-steps.md`) and on plan 3d's folder move (`2026-10-13-03d-history-backup.md`).

## Decisions this plan takes where the spec leaves room, or where the code moved

**Manifest (§3), English-only (plan 5a)**
- `profiles: { label, fields }`. `label` is one English string (1–40), the singular the app uses ("student", "profile"): "Add student", "Choose student". The spec's `{ es, en }` pair no longer exists in the core.
- `fields` (1–6, each once) are the fields of the `profile` collection the **add and edit form** asks for, in order. The first is always `name`. The spec says "shown in the switcher"; the switcher itself only draws the avatar and the name (flagged, product).
- `profiles` needs `data.profile` with `single: true` and `scoped: false` (§3), and a `name` field declared as a string (`z.string()`, with or without bounds, not optional): it is the profile's title. Every listed field must be a field of that schema the core form can draw. All are `superRefine` rules, so `check` reports them as `schema` findings with their paths, as plans 4–6 did. `check` adds no warning of its own.
- The `profile` collection is an ordinary collection otherwise: the harness picks its `agent` permission and its `context` (the agent learns who it talks to only through `context`).

**The registry and the active profile (§4)**
- `<root>/.harness/profiles.json`: `{ "version": 1, "profiles": [{ id, title, color?, createdAt, archived }] }`. The spec also lists "last active id"; this plan keeps the active profile **only** in `config.json` → `profile` (§4 "Shared engine config"), so there is one source of truth (flagged, technical).
- An id is a slug of the first name (`sofi`, `sofi-2`), lowercase letters, digits and dashes, at most 40, never a name already used in the registry **or by any entry of the root folder** (a folder "Sofi" made by hand is never reused). Renaming changes only the title (§4).
- The registry copies `name` (as `title`) and `color` from the profile's record whenever that record changes, from any writer (§4 "The registry copies the colour"). A colour is kept only when it is lowercase letters (≤ 20); the window draws it only when it is one of `PROFILE_COLORS`.
- `config.json` keeps `profile` like `folder`: `hh:saveConfig` never takes it from the window; only the switch writes it (`ConfigStore.setProfile`). At start, a `profile` the registry doesn't list, or lists as archived, is cleared.
- The root's `.harness/` holds only `profiles.json`. No history tracks the root (§4 "History").

**Where each thing is read (D2, D3)**
- **Per profile**, through `baseOf`: tasks, chats, notes, scopes, data, settings (they are the `settings` collection), `setup.json`, usage, AGENTS.md/CLAUDE.md, the runtime's working folder and its history (`historyDir(userData, <root>/<profile>)`), `hh:openPath`/`hh:revealPath` (a path the agent names is relative to its working folder).
- **App-wide**: the engine and its sign-in, `config.json` (models, language, appearance, text size, `backupDismissed`), the folder's place (`hh:revealFolder`, Settings › General's folder row, the backup status and notice, "Move folder…"), the reference folders.
- `validConfig()` is null in a profiles app until a profile is active, so nothing under `.harness/` is read or written while no profile is active. `baseOf` throws rather than answer the root of a profiles app.

**The first profile, and adding one (§5 "Creating a profile")**
- **Flagged, product.** The setup screen gets one core step after "AI engine", **"Who's using <name>?"** (stepper label "Who's using it"), shown only when the harness has `profiles`: on the first run, and whenever the person presses "Add <label>". It draws the `profiles.fields` form (the core `InputForm`). Next creates the profile and makes it active; the flow then goes on with that profile's harness steps (plan 6), then "All set".
- Home, in a profiles app with no active profile, says "One step left: add a <label>", and "Set up <name>" opens the setup screen at that step.
- Creating runs inside the switch (below): the open task closes first; then the registry entry, `prepareFolder(<root>/<id>, seed)`, the `profile` record (as the person, app-wide, through that profile's data store); then the runtime closes and `config.json` names the new profile. Its settings take their defaults with no write (plan 3), and its setup steps start missing (plan 6: a fresh folder has no `tasks.json`).
- The fields are checked against the `profile` schema before anything is made; a refusal comes back by field.
- The setup screen's title names the person once a profile is active: "Set up Family Tutor for Sofi".

**Switching (§5 "Switching profiles")**
- `ProfileSwitch.run(target)`: refused (`busy`) while quitting, while a task operation or a turn runs, while turns are held (engine change, folder move, engine update) or a restore runs, or while another switch runs. The check and the flag happen with no `await` between them. While it runs, `turnBlocked()` says "Switching profiles": new turns, restores and moves are refused.
- Then: the open task closes with its closing turn and note (`tasks.finish()`); a closing turn the person stopped leaves the task open and refuses the switch (`open`). Then `target()` (an existing id, or creating one), `closeRuntime()`, `config.setProfile(id)`, and the arrival.
- **Arrival:** a task left open in the new profile (a crash) ends unfinished (`tasks.interrupt()`); the settings controller forgets the old AGENTS.md and re-reads (`forget()`, `changed()`); the scopes migrate and are sent (`settleScopes`, `scopesChanged`); the setup steps' state and the task view are sent. The window then gets the new `AppState` from the result and redraws Home.
- Switching to the active profile is a no-op (`ok`).

**Archive and delete (§5)**
- Neither works on the **active** profile (`active`): switch first. The spec's "the last active profile cannot be deleted" is read as "the active one" (flagged, product). Since one profile is always active once the first exists, the last profile can never be deleted either.
- Archive hides the profile from the switcher; Settings lists it with "Bring back".
- Delete asks twice in the window. The main process puts `<root>/<id>` in the system Trash (`shell.trashItem`), then the profile's history folder (`historyDir(userData, <root>/<id>)`, when it exists), then drops the registry entry. A folder that is already gone is skipped. A failed Trash for the folder refuses the delete (`failed`) and changes nothing; a failed Trash for the history is logged and leaves it where it is.

**The window**
- **Switcher** (Home's top bar and the work screen's, next to the scope picker): the avatar (the first letter of the title on its colour) and the name; with two or more active profiles, a select. Then "Add <label>". Disabled while a turn runs. A refusal shows one line: "Wait until the AI finishes, then try again." (`busy`), "The open topic is still closing. Try again." (`open`), "That didn't work. Try again." (anything else).
- **Privacy note** (§6): on the profile step, only when exactly one active profile exists already (so it shows while the second one is created, once): "Profiles keep each person's work apart, but they don't protect it: anyone who uses this computer can open any profile."
- **Settings › General › People** (only with `profiles`): one row per profile with its avatar and name. The active one says "In use now" and has "Edit" (its `profiles.fields` form in place, saved through `client.data.put("profile", …)`: the person's write, with its checks and its `Data: profile` commit). Every other one has "Archive" (or "Bring back") and "Delete…". Delete asks: "Delete Tomás? This can't be undone from the app." [Delete] [Cancel], then "Tomás's folder and history go to the Trash. You can still get them back from there." [Move to the Trash] [Cancel].
- **Settings › Usage** sums every profile (§4 "Usage") and adds "Usage by person" (tokens per profile, most first). The per-scope list shows the active profile's scopes only (scope ids repeat across profiles).

**Shared views (§8 slice 3)**
- **Usage.** `profilesUsage` merges every profile's records (each `UsageLog.load()`, the active engine's only) in time order, then runs `summarizeUsage` on the merged list: the plan window is shared, so consecutive records across people measure it right.
- **Engine change.** The active profile's chat is archived as today; every other profile's chat is archived right away too (`archiveChatsOnEngineChange`). Only the active profile can have an open task (a switch closes it); one left by a crash ends at arrival.
- **Moving the folder.** `MoveDeps.subfolders()` (only in a profiles app) lists the registry's ids. The tracked files compared after the copy are every profile's, each prefixed with its id; the notes are made relative in each profile folder; each profile's history moves to its new place, and a failure puts every moved one back (§4 "rolls them all back if any fails"). The journal records `histories: [{ rel, setAside? }]`; `recoverMove` settles each. Without `subfolders` the code path and journal are today's (D0).

**Spec §9 open questions (simplest default consistent with the spec, flagged)**
- **Q1 (a harness adds `profiles` later):** no migration in this plan. A folder used before keeps its root files where they are, untouched and unread; the first profile starts empty. The spec's proposal (a one-time migration that asks first) is left to a later plan; Docs list it as a known gap. No released harness has data yet.
- **Q2 (shared material):** accepted as the spec proposes: each profile processes its own material. No app-wide library.
- **Q3 (Settings › Modelos per profile):** no, app-wide, as the spec proposes (D3): `config.json` → `models` is untouched.

**Not in this plan (flagged)**
- An avatar image: the avatar is the title's first letter on its colour.
- Editing a profile that isn't active (its record lives in another folder's history): switch first.
- `humanharness run`: its folder works as one profile's folder; it reads no registry.

import { randomUUID } from "node:crypto";
import { promises as fs } from "node:fs";
import path from "node:path";
import { profilesFile } from "./layout";

/** A profile id: a slug of its first name. It names the profile's folder inside the app's folder (spec D2). */
export const PROFILE_ID = /^[a-z0-9][a-z0-9-]{0,39}$/;
export const isProfileId = (v: unknown): v is string => typeof v === "string" && PROFILE_ID.test(v);
export const PROFILE_TITLE_MAX = 40;
const SLUG_MAX = 32;
/** A colour the registry keeps: a plain word; the window decides whether it can draw it. */
const COLOR = /^[a-z]{1,20}$/;

/** One entry of `profiles.json` (spec §4). The id never changes; renaming changes only the title. */
export interface ProfileEntry {
  id: string;
  title: string;
  color?: string;
  createdAt: string;
  archived: boolean;
}

/** The title as stored: one line, trimmed, 1–40 characters. Throws otherwise. */
export function cleanProfileTitle(title: unknown): string {
  const t = typeof title === "string" ? title.replace(/\s*\n\s*/g, " ").trim() : "";
  if (!t || t.length > PROFILE_TITLE_MAX) throw new Error(`A profile's name is 1–${PROFILE_TITLE_MAX} characters`);
  return t;
}

/** A slug of `title` (`sofi`), numbered when `taken` holds it (`sofi-2`); "profile" when nothing is left. */
export function profileSlug(title: string, taken: ReadonlySet<string>): string {
  const base =
    title
      .normalize("NFKD")
      .replace(/[̀-ͯ]/g, "")
      .toLowerCase()
      .replace(/[^a-z0-9]+/g, "-")
      .replace(/^-+|-+$/g, "")
      .slice(0, SLUG_MAX)
      .replace(/-+$/, "") || "profile";
  let id = base;
  for (let i = 2; taken.has(id); i++) id = `${base}-${i}`;
  return id;
}

/** The folder of profile `id` inside the app's folder. Throws for anything that isn't a profile id. */
export function profileDir(root: string, id: string): string {
  if (!isProfileId(id)) throw new Error(`Invalid profile: "${id}"`);
  return path.join(root, id);
}

const isObject = (v: unknown): v is Record<string, unknown> => typeof v === "object" && v !== null && !Array.isArray(v);
const colorOf = (v: unknown): { color?: string } => (typeof v === "string" && COLOR.test(v) ? { color: v } : {});

function cleanEntry(v: unknown): ProfileEntry | null {
  if (!isObject(v) || !isProfileId(v.id) || typeof v.title !== "string" || !v.title.trim()) return null;
  return { id: v.id, title: v.title, ...colorOf(v.color), createdAt: typeof v.createdAt === "string" ? v.createdAt : "", archived: v.archived === true };
}

/** The profile registry of the app's folder. Writes are atomic and one at a time. */
export class ProfileStore {
  private readonly file: string;
  private writes: Promise<unknown> = Promise.resolve();

  constructor(
    private readonly root: string,
    private readonly now: () => Date = () => new Date(),
  ) {
    this.file = profilesFile(root);
  }

  /** In creation order. A missing file is empty; one that isn't JSON is set aside as `profiles.json.corrupt-<time>`. */
  async list(): Promise<ProfileEntry[]> {
    let text: string;
    try {
      text = await fs.readFile(this.file, "utf8");
    } catch (err) {
      if ((err as NodeJS.ErrnoException).code === "ENOENT") return [];
      throw err;
    }
    let raw: unknown;
    try {
      raw = JSON.parse(text);
    } catch {
      await fs.rename(this.file, `${this.file}.corrupt-${Date.now()}`);
      return [];
    }
    const seen = new Set<string>();
    const out: ProfileEntry[] = [];
    for (const v of isObject(raw) && Array.isArray(raw.profiles) ? raw.profiles : []) {
      const e = cleanEntry(v);
      if (e && !seen.has(e.id)) {
        seen.add(e.id);
        out.push(e);
      }
    }
    return out;
  }

  /** A new profile. Its id is never one the registry or the root folder already has (any case). */
  create(title: unknown, color?: string): Promise<ProfileEntry> {
    const clean = cleanProfileTitle(title);
    return this.change(async (list) => {
      const onDisk = await fs.readdir(this.root).catch(() => [] as string[]);
      const taken = new Set([...list.map((p) => p.id), ...onDisk.map((n) => n.toLowerCase())]);
      const entry: ProfileEntry = { id: profileSlug(clean, taken), title: clean, ...colorOf(color), createdAt: this.now().toISOString(), archived: false };
      return [[...list, entry], entry];
    });
  }

  /** The registry's copy of the profile's record: its name and colour (spec §4). */
  setIdentity(id: string, identity: { title: unknown; color?: unknown }): Promise<ProfileEntry> {
    const title = cleanProfileTitle(identity.title);
    return this.update(id, (p) => {
      const { color: _old, ...rest } = p;
      return { ...rest, title, ...colorOf(identity.color) };
    });
  }

  setArchived(id: string, archived: boolean): Promise<ProfileEntry> {
    return this.update(id, (p) => ({ ...p, archived }));
  }

  /** Drops the entry; the caller has put the folder in the Trash first. */
  remove(id: string): Promise<void> {
    return this.change(async (list) => {
      if (!list.some((p) => p.id === id)) throw new Error(`Unknown profile: "${id}"`);
      return [list.filter((p) => p.id !== id), undefined];
    });
  }

  private update(id: string, fn: (p: ProfileEntry) => ProfileEntry): Promise<ProfileEntry> {
    return this.change(async (list) => {
      const i = list.findIndex((p) => p.id === id);
      if (i < 0) throw new Error(`Unknown profile: "${id}"`);
      const next = fn(list[i]);
      return [list.map((p, j) => (j === i ? next : p)), next];
    });
  }

  private change<T>(fn: (list: ProfileEntry[]) => Promise<[ProfileEntry[], T]>): Promise<T> {
    const run = this.writes.then(async () => {
      const [list, result] = await fn(await this.list());
      await fs.mkdir(path.dirname(this.file), { recursive: true });
      const tmp = `${this.file}.${randomUUID()}.tmp`;
      try {
        await fs.writeFile(tmp, `${JSON.stringify({ version: 1, profiles: list }, null, 2)}\n`);
        await fs.rename(tmp, this.file);
      } catch (err) {
        await fs.rm(tmp, { force: true });
        throw err;
      }
      return result;
    });
    this.writes = run.catch(() => undefined);
    return run;
  }
}

```ts
export interface ProfileSwitchDeps {
  quitting(): boolean;
  /** A task operation or a turn is under way. */
  busy(): boolean;
  /** Why turns are held now (an engine change, a folder move, an engine update, a restore), or null. */
  turnBlocked(): string | null;
  /** Closes the open task with its closing turn and note (`tasks.finish()`); false when that turn was stopped. */
  closeTask(): Promise<boolean>;
  /** Closes the runtime, which runs in the old profile's folder; the next turn starts one in the new folder. */
  closeRuntime(): Promise<void>;
  /** Saves the active profile (`ConfigStore.setProfile`). */
  saveActive(id: string): Promise<void>;
  /** The new profile is active: settle its folder and tell the window. A failure is logged; the switch stands. */
  arrived(id: string): Promise<void>;
}

export type ProfileSwitchResult = { ok: true; id: string } | { ok: false; reason: "busy" | "open" | "failed" };

/**
 * Switching profiles against turns, restores and moves (profiles spec §5): refused while any of them runs, and all of
 * them held off from its first moment until it ends. The check and the flag happen with no await in between, so a
 * send, a restore or a move can't slip in (each one checks `turnBlocked()`).
 */
export class ProfileSwitch {
  private pending = false;

  constructor(private readonly d: ProfileSwitchDeps) {}

  /** Why a turn, a restore or a move can't start now because of a switch, or null. */
  turnBlocked(): string | null {
    return this.pending ? "Switching profiles" : null;
  }

  /**
   * Switches to the profile `target` names. `target` runs after the open task closed and before the runtime closes, so
   * creating a profile happens inside the switch: a refused switch makes nothing.
   */
  async run(target: () => Promise<string>): Promise<ProfileSwitchResult> {
    if (this.pending || this.d.quitting() || this.d.busy() || this.d.turnBlocked()) return { ok: false, reason: "busy" };
    this.pending = true;
    try {
      if (!(await this.d.closeTask())) return { ok: false, reason: "open" };
      const id = await target();
      await this.d.closeRuntime();
      await this.d.saveActive(id);
      await this.d.arrived(id).catch((err: unknown) => console.error("Could not settle the new profile", err));
      return { ok: true, id };
    } catch (err) {
      console.error("Could not switch profiles", err);
      return { ok: false, reason: "failed" };
    } finally {
      this.pending = false;
    }
  }
}

import type { Collection, DataRecord } from "@humanharness/harness-sdk";
import { ProfileStore, cleanProfileTitle, isProfileId, prepareFolder, profileDir } from "@humanharness/workspace";
import type { InputIssue, ProfileRefusal, ProfilesState } from "@humanharness/ui/client";
import { profileOfBase } from "./profile-base";
import type { ProfileSwitchResult } from "./profile-switch";

export interface ProfilesDeps {
  /** The app's folder (`config.json` → `folder`); null before it is chosen. */
  root(): Promise<string | null>;
  /** The active profile (`config.json` → `profile`). */
  active(): Promise<string | undefined>;
  /** The harness's `profile` collection: its schema checks a new profile's fields before anything is made. */
  collection: Collection;
  /** The harness's seed folder, copied into a new profile's folder (`prepareFolder`). */
  seed?: string;
  /** Writes a new profile's record in its own folder: that folder's data store, as the person, app-wide. */
  writeRecord(base: string, record: DataRecord): Promise<void>;
  /** A profile's record, read from its own folder; null when there is none. */
  readRecord(base: string): Promise<DataRecord | null>;
  /** The switch (`ProfileSwitch.run`). */
  switchTo(target: () => Promise<string>): Promise<ProfileSwitchResult>;
  /** Puts a file or folder in the system Trash (Electron's `shell.trashItem`). Never a permanent delete. */
  trash(p: string): Promise<void>;
  /** Where the history of a folder lives (`historyDir`). */
  historyDir(folder: string): string;
  /** The profiles changed: the window's switcher redraws. */
  changed(state: ProfilesState): void;
}

/** How a change went, before the main process adds the new app state. */
export type ProfileOutcome = { ok: true } | { ok: false; reason: ProfileRefusal; errors?: InputIssue[] };

const exists = (p: string) => fs.access(p).then(() => true, () => false);

/** The profiles of the app's folder (profiles spec §4, §5). Every refusal comes back as data. */
export class Profiles {
  private readonly stores = new Map<string, ProfileStore>();

  constructor(private readonly d: ProfilesDeps) {}

  /** One registry per root, so its write queue orders every change. */
  private store(root: string): ProfileStore {
    let store = this.stores.get(root);
    if (!store) {
      store = new ProfileStore(root);
      this.stores.set(root, store);
    }
    return store;
  }

  async state(): Promise<ProfilesState> {
    const root = await this.d.root();
    if (!root) return { active: null, list: [] };
    const list = await this.store(root).list();
    const active = await this.d.active();
    return { active: active !== undefined && list.some((p) => p.id === active && !p.archived) ? active : null, list };
  }

  /** Whether `id` can be the active profile: registered and not archived. */
  async openable(id: string): Promise<boolean> {
    const root = await this.d.root();
    return root !== null && (await this.store(root).list()).some((p) => p.id === id && !p.archived);
  }

  /**
   * A new profile from the add form's fields (spec §5 "Creating a profile"), made inside the switch: the open task
   * closes first, then the registry entry, the folder (with the seed) and the record; then it is the active profile.
   */
  async create(values: unknown): Promise<ProfileOutcome> {
    const root = await this.d.root();
    if (!root) return { ok: false, reason: "not-ready" };
    const parsed = this.d.collection.schema.safeParse(values);
    if (!parsed.success) {
      return { ok: false, reason: "invalid", errors: parsed.error.issues.map((i) => ({ path: i.path.map(String).join("."), message: i.message })) };
    }
    const record = parsed.data as DataRecord;
    let title: string;
    try {
      title = cleanProfileTitle(record.name);
    } catch (err) {
      return { ok: false, reason: "invalid", errors: [{ path: "name", message: (err as Error).message }] };
    }
    return this.answer(
      await this.d.switchTo(async () => {
        const entry = await this.store(root).create(title, typeof record.color === "string" ? record.color : undefined);
        const base = profileDir(root, entry.id);
        await prepareFolder(base, this.d.seed);
        await this.d.writeRecord(base, record);
        return entry.id;
      }),
    );
  }

  /** Makes `id` the active profile; the open task closes first. */
  async open(id: unknown): Promise<ProfileOutcome> {
    const root = await this.d.root();
    if (!root) return { ok: false, reason: "not-ready" };
    if (!isProfileId(id) || !(await this.openable(id))) return { ok: false, reason: "unknown" };
    if ((await this.d.active()) === id) return { ok: true };
    return this.answer(await this.d.switchTo(async () => id));
  }

  /** Hides a profile from the switcher, or brings it back. Never the active one. */
  async setArchived(id: unknown, archived: boolean): Promise<ProfileOutcome> {
    const root = await this.d.root();
    if (!root) return { ok: false, reason: "not-ready" };
    if (!isProfileId(id) || !(await this.store(root).list()).some((p) => p.id === id)) return { ok: false, reason: "unknown" };
    if ((await this.d.active()) === id) return { ok: false, reason: "active" };
    await this.store(root).setArchived(id, archived);
    this.d.changed(await this.state());
    return { ok: true };
  }

  /**
   * Deletes a profile (spec §5): its folder goes to the system Trash, then its history; then the entry goes. Never the
   * active one. A Trash that refuses the folder changes nothing; one that refuses the history leaves it (logged).
   */
  async remove(id: unknown): Promise<ProfileOutcome> {
    const root = await this.d.root();
    if (!root) return { ok: false, reason: "not-ready" };
    if (!isProfileId(id) || !(await this.store(root).list()).some((p) => p.id === id)) return { ok: false, reason: "unknown" };
    if ((await this.d.active()) === id) return { ok: false, reason: "active" };
    const dir = profileDir(root, id);
    try {
      if (await exists(dir)) await this.d.trash(dir);
    } catch (err) {
      console.error("Could not put the profile's folder in the Trash; nothing was changed", err);
      return { ok: false, reason: "failed" };
    }
    const history = this.d.historyDir(dir);
    if (await exists(history)) await this.d.trash(history).catch((err: unknown) => console.error("Could not put the profile's history in the Trash", err));
    await this.store(root).remove(id);
    this.d.changed(await this.state());
    return { ok: true };
  }

  /**
   * A profile's record changed (any writer): the registry copies its name and colour (spec §4). `base` is the folder
   * whose store changed; anything that isn't a profile's folder, or a record without a usable name, changes nothing.
   */
  async sync(base: string): Promise<void> {
    const root = await this.d.root();
    const id = root ? profileOfBase(root, base) : null;
    if (!root || !id) return;
    const record = await this.d.readRecord(base);
    if (!record) return;
    try {
      cleanProfileTitle(record.name);
    } catch {
      return;
    }
    await this.store(root).setIdentity(id, { title: record.name, color: record.color });
    this.d.changed(await this.state());
  }

  private async answer(r: ProfileSwitchResult): Promise<ProfileOutcome> {
    if (!r.ok) return { ok: false, reason: r.reason };
    this.d.changed(await this.state());
    return { ok: true };
  }
}

export type PersonUsageRecord = UsageRecord & { person: string };

/** Every profile's records in one list, oldest first (a stable sort keeps each log's own order for equal times). */
export function mergeUsage(byProfile: Record<string, UsageRecord[]>): PersonUsageRecord[] {
  return Object.entries(byProfile)
    .flatMap(([person, records]) => records.map((r) => ({ ...r, person })))
    .sort((a, b) => (a.at < b.at ? -1 : a.at > b.at ? 1 : 0));
}

 * turns, in time order, measure its window and estimates. `scopes` are the active profile's only (scope ids repeat
 * across people); `profiles` counts every turn's tokens per profile.
 */
export function profilesUsage(byProfile: Record<string, UsageRecord[]>, activeProfile: string, primary: string | undefined, now: Date = new Date()): UsageSummary {
  const merged = mergeUsage(byProfile);
  const { scopes: _everyone, ...summary } = summarizeUsage(merged, primary, now);

import { useEffect, useState } from "react";
import { useTranslation } from "react-i18next";
import type { AppState, HarnessClient, ProfileResult, ProfileView, ProfilesState } from "./client";
import { AVATAR_COLORS } from "./profiles";

/** A profile's avatar (spec D7): the title's first letter on its colour; neutral when the colour is not one we draw. */
export function Avatar({ profile }: { profile: Pick<ProfileView, "title" | "color"> }) {
  const color = profile.color && (AVATAR_COLORS as readonly string[]).includes(profile.color) ? profile.color : undefined;
  return (
    <span className="hh-avatar" data-color={color} aria-hidden="true">
      {[...profile.title.trim()][0]?.toUpperCase() ?? ""}
    </span>
  );
}

/** Reads the profiles and follows every change (a change that arrived is newer than the first reply). */
export function useProfiles(client: HarnessClient, on: boolean): ProfilesState | null {
  const [profiles, setProfiles] = useState<ProfilesState | null>(null);
  useEffect(() => {
    if (!on) return;
    let live = true;
    let seen = false;
    client.profiles.get().then(
      (s) => {
        if (live && !seen) setProfiles(s);
      },
      () => undefined,
    );
    const off = client.profiles.onChange((s) => {
      seen = true;
      if (live) setProfiles(s);
    });
    return () => {
      live = false;
      off();
    };
  }, [client, on]);
  return profiles;
}

/** The refusal's line; every reason the person can't act on is "didn't work". */
export const refusalKey = (r: Exclude<ProfileResult, { ok: true }>): string =>
  `profiles.refused.${r.reason === "busy" || r.reason === "open" ? r.reason : "failed"}`;

/**
 * Who is using the app (spec §5 "Where the switcher lives"): the active profile's avatar and name, a select when there
 * are several, and Add. Shown only in a harness with profiles.
 */
export function ProfileSwitcher({
  client,
  state,
  onSwitched,
  onAdd,
  disabled = false,
}: {
  client: HarnessClient;
  state: AppState;
  /** A switch went through: the app state with the new profile. */
  onSwitched: (state: AppState) => void;
  /** "Add <label>": the setup screen at its profile step. */
  onAdd: () => void;
  disabled?: boolean;
}) {
  const { t } = useTranslation();
  const profiles = useProfiles(client, state.profiles !== undefined);
  const [error, setError] = useState<string | null>(null);
  if (!state.profiles || !profiles) return null;
  const label = state.profiles.label;
  const shown = profiles.list.filter((p) => !p.archived);
  const active = shown.find((p) => p.id === profiles.active);
  const pick = (id: string) => {
    setError(null);
    client.profiles.open(id).then(
      (r) => (r.ok ? onSwitched(r.state) : setError(t(refusalKey(r)))),
      () => setError(t("profiles.refused.failed")),
    );
  };
  return (
    <div className="hh-profile-switcher">
      {active && <Avatar profile={active} />}
      {shown.length > 1 ? (
        <select aria-label={t("profiles.pick", { label })} value={active?.id ?? ""} disabled={disabled} onChange={(e) => pick(e.target.value)}>
          {!active && <option value="" disabled />}
          {shown.map((p) => (
            <option key={p.id} value={p.id}>
              {p.title}
            </option>
          ))}
        </select>
      ) : (
        active && <span className="hh-profile-name">{active.title}</span>
      )}
      <button type="button" disabled={disabled} onClick={onAdd}>
        {t("profiles.add", { label })}
      </button>
      {error && <p role="alert">{error}</p>}
    </div>
  );
}

import { useState } from "react";
import { useTranslation } from "react-i18next";
import type { AppState, HarnessClient, InputIssue } from "./client";
import { InputForm } from "./InputForm";
import { refusalKey } from "./ProfileSwitcher";

/**
 * The profile step's body (profiles spec §5 "Creating a profile"): the `profiles.fields` form; its submit creates the
 * profile, which becomes the active one. The privacy note shows while the second profile is made (§6). The setup
 * screen's footer submits it (`formId`).
 */
export function ProfileStep({
  client,
  state,
  formId,
  others,
  onCreated,
}: {
  client: HarnessClient;
  state: AppState;
  formId: string;
  /** How many profiles are there already (not archived). */
  others: number;
  onCreated: (state: AppState) => void;
}) {
  const { t } = useTranslation();
  const [errors, setErrors] = useState<InputIssue[]>([]);
  const [sending, setSending] = useState(false);
  if (!state.profiles) return null;
  const submit = (value: Record<string, unknown>) => {
    setSending(true);
    setErrors([]);
    client.profiles
      .create(value)
      .then(
        (r) => {
          if (r.ok) onCreated(r.state);
          else setErrors(r.errors && r.errors.length > 0 ? r.errors : [{ path: "", message: t(refusalKey(r)) }]);
        },
        () => setErrors([{ path: "", message: t("profiles.refused.failed") }]),
      )
      .finally(() => setSending(false));
  };
  return (
    <>
      {others === 1 && <p className="hh-caption">{t("profiles.privacy")}</p>}
      <InputForm spec={state.profiles.form} data={null} formId={formId} disabled={false} sending={sending} errors={errors} submit={submit} />
    </>
  );
}
```

import { useEffect, useId, useState } from "react";
import { useTranslation } from "react-i18next";
import type { AppState, HarnessClient, InputIssue, InputSpec, ProfileResult } from "./client";
import { InputForm } from "./InputForm";
import { PROFILE_COLLECTION } from "./profiles";
import { Avatar, useProfiles } from "./ProfileSwitcher";

/**
 * Settings › General › People (profiles spec §5): every profile; the active one can be edited, any other archived,
 * brought back or deleted (asked twice; its folder and history go to the Trash).
 */
export function ProfilesSection({ client, state, onChange }: { client: HarnessClient; state: AppState; onChange: (s: AppState) => void }) {
  const { t } = useTranslation();
  const headingId = useId();
  const people = useProfiles(client, state.profiles !== undefined);
  const [editing, setEditing] = useState(false);
  const [confirm, setConfirm] = useState<{ id: string; stage: 1 | 2 } | null>(null);
  const [failed, setFailed] = useState(false);
  if (!state.profiles || !people) return null;
  const form = state.profiles.form;
  const act = (call: Promise<ProfileResult>) => {
    setFailed(false);
    call.then(
      (r) => (r.ok ? onChange(r.state) : setFailed(true)),
      () => setFailed(true),
    );
  };
  return (
    <section aria-labelledby={headingId}>
      <h3 id={headingId}>{t("profiles.sectionTitle")}</h3>
      <ul className="hh-rows" aria-labelledby={headingId}>
        {people.list.map((p) => {
          const active = p.id === people.active;
          return (
            <li key={p.id} className="hh-row hh-row-wrap" aria-label={p.title}>
              <Avatar profile={p} />
              <span>{p.title}</span>
              {active && <span className="hh-caption">{t("profiles.active")}</span>}
              {p.archived && <span className="hh-caption">{t("profiles.archived")}</span>}
              {active ? (
                <button aria-expanded={editing} onClick={() => setEditing((e) => !e)}>
                  {t("profiles.edit")}
                </button>
              ) : (
                <>
                  <button onClick={() => act(p.archived ? client.profiles.unarchive(p.id) : client.profiles.archive(p.id))}>
                    {t(p.archived ? "profiles.unarchive" : "profiles.archive")}
                  </button>
                  <button onClick={() => setConfirm({ id: p.id, stage: 1 })}>{t("profiles.delete")}</button>
                </>
              )}
              {confirm?.id === p.id && (
                <div className="hh-row-note">
                  <p>{t(confirm.stage === 1 ? "profiles.deleteFirst" : "profiles.deleteSecond", { name: p.title })}</p>
                  <button

/** The active profile's fields, saved as the person's write (its checks, its `Data: profile` commit). */
function ProfileEdit({ client, form, onSaved }: { client: HarnessClient; form: InputSpec; onSaved: () => void }) {
  const { t } = useTranslation();
  const [initial, setInitial] = useState<Record<string, unknown> | null>(null);
  const [errors, setErrors] = useState<InputIssue[]>([]);
  const [sending, setSending] = useState(false);
  useEffect(() => {
    let live = true;
    client.data.get(PROFILE_COLLECTION).then(
      (r) => {
        if (live) setInitial(r ?? {});
      },
      () => {
        if (live) setInitial({});
      },
    );
    return () => {
      live = false;
    };
  }, [client]);
  if (initial === null) return <div aria-busy="true" />;
  const submit = (value: Record<string, unknown>) => {
    setSending(true);
    setErrors([]);
    client.data
      .put(PROFILE_COLLECTION, { ...initial, ...value })
      .then(onSaved, () => setErrors([{ path: "", message: t("profiles.refused.failed") }]))
      .finally(() => setSending(false));
  };
  return <InputForm spec={{ ...form, submitLabel: t("profiles.save") }} data={null} initial={initial} disabled={false} sending={sending} errors={errors} submit={submit} />;
}

```md
# Profiles

Several people use one app on one computer, each with their own work. A harness turns this on with `profiles` in its
manifest. Without it, nothing on this page happens: the app works on one folder, as before.

## The manifest

    profiles: { label: "student", fields: ["name", "color", "ageBand"] }

- `label`: the English singular the app uses: "Add student", "Choose student".
- `fields`: the fields of the `profile` collection the add and edit form asks for, in order. The first is `name`.
- It needs a `profile` collection with `single: true`, `scoped: false` and a `name` string. `check` reports a missing
  or wrong one as a `schema` finding.
- The agent learns who it talks to only through the collection's own `context`.
- `PROFILE_COLORS` (from `@humanharness/harness-sdk`) are the colours an avatar can take.

## On disk

    <folder>/
      .harness/profiles.json       the registry: { version: 1, profiles: [{ id, title, color?, createdAt, archived }] }
      sofi/                        one profile: everything a folder held before (.harness/, notes, AGENTS.md…)
      tomas/

- The id is a slug of the first name (`sofi`, `sofi-2`), never a name already used in the folder.
- `title` and `color` are copies of the profile's record; the registry follows every write to it.
- The active profile is `config.json` → `profile`. Only a switch writes it.
- Each profile has its own history: `historyDir(userData, <folder>/<id>)`. Nothing tracks the root.

## What is per profile, what is app-wide

- Per profile: tasks, chats, notes, scopes, data, settings, setup steps, usage, AGENTS.md, the agent's working folder
  and its history.
- App-wide: the engine and its sign-in, models, language, appearance, the folder's place, its backup, reference folders.
- In code: `baseOf(config)` is `<folder>/<profile>` in a profiles app and `<folder>` otherwise. It throws in a profiles
  app with no active profile; `validConfig()` is null then, so nothing under `.harness/` is touched.

## Switching (`profile-switch.ts`)

1. Refused (`busy`) while a turn, a task operation, a restore, a move, an engine change or another switch runs.
2. The open task closes with its closing turn and note. A stopped closing turn refuses the switch (`open`).
3. The target is opened or created; the runtime closes; `config.json` names the profile.
4. Arrival: a task left open by a crash ends unfinished; settings, scopes, setup steps and tasks are re-sent.

New turns, restores and moves are refused while a switch runs ("Switching profiles").

## Creating, archiving, deleting (`profiles.ts`)

- Create: the fields are checked first. Then the registry entry, the seeded folder, the `profile` record (the person's
  write), then the switch. The setup screen shows this as the "Who's using it" step, then the profile's own setup steps.
- Archive hides a profile from the switcher. Settings › General › People brings it back.
- Delete asks twice. The folder, then its history, go to the system Trash; then the entry goes. Nothing is deleted for good.
- Neither works on the active profile.

## Shared views

- Usage: every profile's records merged in time order, then summed. "Usage by person" lists tokens per profile.
  The per-scope list shows the active profile's scopes.
- Engine change: every profile's chat is archived.
- Moving the folder: every profile's history moves; a failure puts them all back. The journal lists them (`histories`).

## Privacy

Profiles keep work apart; they don't protect it. There is no password. The window says so once, while the second
profile is created.

## Known gaps

- A harness that adds `profiles` after people used it: the old root files stay where they are, unread. No migration yet.
- No avatar image: the title's first letter on its colour.
- Only the active profile can be edited.
- `humanharness run` works on one folder and reads no registry.
```
