# Spike: plugin backend sandbox, custom scheme and zod JSON Schema round trip (2026-10-27)

Checks the assumptions of the Plugins part 1 plan (`docs/superpowers/plans/2026-10-27-plugins-part1.md`, Task 1) with the repo's own Electron (44.7.0, `packages/shell`) and zod (4.6.5, `packages/harness-sdk`). Nothing was installed; no network: the only server was the spike's own `http.createServer` on `127.0.0.1:0`, counting every request and WebSocket upgrade.

- Folder: written below as `/tmp/hh-pl-spike/...` for readability; it really ran in the session scratchpad, `/private/tmp/claude-501/-Users-marcozanger-Documents-workspace-humanharness--claude-worktrees-plan-sidekick/<session>/scratchpad/hh-pl-spike/`.
- Files: `main.cjs` (Electron main), `plugin-preload.cjs` (exposes `hh.rpc`; also tries the app channel once for S9), `app-preload.cjs` + `app/index.html` (a control "app page" for S9), `dist/_hh/host.html`, `dist/_hh/host.js`, `dist/backend.js` (runs every escape and reports each outcome over `hh.rpc("report")`), `zod.ts`, `zod2.ts`.
- `main.cjs` runs in three modes so each layer is tested on its own: `all` (CSP header + `webRequest` cancel + navigation guards), `csp` (CSP header + guards; `webRequest` only logs), `filter` (no CSP, no guards; `webRequest` cancels). Each mode loads the page, runs the escapes, crashes the renderer, reloads, and runs them again.

## Results for Tasks 2, 11 and 15

- **Scheme privileges:** `protocol.registerSchemesAsPrivileged([{ scheme: "hh-plugin", privileges: { standard: true, secure: true } }])`. No `corsEnabled`, `supportFetchAPI` or `bypassCSP` needed: module scripts and `import("../backend.js")` load. Side effect: `fetch("hh-plugin://…")` from the page fails (no `supportFetchAPI`; also blocked by `connect-src` via `default-src 'none'`), which is what we want.
- **Preload loading:** a plain CommonJS file at an absolute path (`webPreferences.preload`) works in a `sandbox: true` window; no electron-vite entry needed. It may `require("electron")` (`contextBridge`, `ipcRenderer`).
- **Plugin channel:** global `ipcMain.handle("hh-plugin:rpc", …)` works and gives `event.sender.id` and `event.senderFrame.url`. It also receives calls from the app's own page, so the handler **must** check the sender is a registered plugin window's main frame (as planned).
- **zod conversion:** `z.fromJSONSchema` round-trips every allowlisted keyword, but an object **without** `additionalProperties` passes unknown keys through (catchall `unknown`), at every depth; it does not strip. Fallback taken: Task 2's `jsonSchemaToZod` builds `z.object` itself from `properties`/`required` (recursively, through `items` and `anyOf` too) and uses `z.fromJSONSchema` only for nodes with no object below them; `additionalProperties: false` → `z.strictObject`, `true` → `z.looseObject`, absent → `z.object` (strips). Two more facts Task 2 needs: `z.toJSONSchema(z.object(...))` emits `additionalProperties: false` (default `io: "output"`), and a simple union becomes `"type": ["string", "number"]`, so the allowlist's `type` must accept an array of type names. `z.fromJSONSchema` compiles `pattern` and accepts `$ref`: the allowlist must run **before** it (Decision 3 confirmed).

## S8: zod 4.6 JSON Schema round trip

`zod.ts`: for each keyword, a zod schema → `z.toJSONSchema` → `z.fromJSONSchema`, then `safeParse` of 6 valid and 6 invalid values on both. `uniqueItems` (zod has no builder for it) was a hand-written `{ type: "array", uniqueItems: true }`.

```
same  string / number / integer / boolean / array(items) / enum / const / anyOf / minimum+maximum /
      exclusiveMinimum+exclusiveMaximum / multipleOf / minLength+maxLength / minItems+maxItems /
      uniqueItems / object required + additionalProperties:false / default / title+description
MISMATCH object (no additionalProperties): {"a":"x","c":1} orig=true back=false
```

The mismatch is on the way **out**: `z.toJSONSchema(z.object({ a }))` writes `"additionalProperties": false`, so the round-tripped schema refuses extra keys that the original stripped. `io: "input"` omits it, and then:

```
fromJSONSchema({type:"object",properties:{a:{type:"string"}}}) instanceof ZodObject: true, shape keys ["a"]
unknown keys, no additionalProperties:  {"a":"x","extra":1}     ← passed through, not stripped (catchall "unknown"), nested too
unknown keys, additionalProperties:false: refused
unknown keys, additionalProperties:true:  kept
fromJSONSchema({type:"string"}) instanceof ZodString: true; integer/number → ZodNumber; enum → ZodEnum; boolean → ZodBoolean; array → ZodArray
missing non-required key: accepted; default filled on parse: {"a":"hi"}
title/description kept (description: "D", registry meta { title, description })
{"type":["string","number"]} → ZodUnion (string ok, number ok, boolean refused)
pattern: compiled and enforced; $ref + $defs: accepted
```

`.strip()` on the top object strips only that level (nested objects keep extra keys); building `z.object` per property strips at every level:

```
own z.object per property: {"a":"x","n":{"c":"y"}}   (input {"a":"x","n":{"c":"y","deep":1},"extra":1})
```

**Verdict: partly holds → fallback.** `jsonSchemaToZod` (Task 2) walks the allowlisted JSON Schema itself: object nodes become `z.object` / `z.strictObject` / `z.looseObject` from `properties` and `required` (non-required → `.optional()`, recursively), and the walk also recurses into `items` and `anyOf` so an object nested there is built the same way; only nodes with no object below them go through `z.fromJSONSchema`. The allowlist check runs first, so `pattern`, `$ref` and friends never reach zod; `type` may be a string or an array of type names.
