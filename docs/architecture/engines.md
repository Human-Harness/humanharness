# Engines

An engine is an official AI command-line tool the person already uses. Human Harness drives that tool and never handles a key: Claude and Codex run on the person's subscription; OpenCode runs on whatever provider (an API key or a local model) the person set up in OpenCode itself.

## The registry

`packages/engines/src/index.ts` describes each engine: its legal status (`allowed`, `pending`, `excluded`) with the source and date, the plan it requires, where data goes, how to detect it (`detect.binary`, `versionArgs`, `minVersion`), its transport and its setup commands (`install`, `login`, `status`, `update`, `logout`). Optional facts only one engine sets so far: `transport.profile` (how a model profile reaches an ACP engine), `reportsCost` (the engine reports real money per turn), `setup.inTerminal` (steps the person runs in Terminal) and `setup.providersUrl`. `availableEngines` keeps the harness's engines that are allowed, plus the pending ones in development.

## Transports

- **Claude** (`packages/runtime/src/claude-cli.ts`): one `claude -p` process per turn with `--output-format stream-json`; the message goes in through stdin. A new session starts with `--session-id <uuid>`, later turns use `--resume`. Tools come from the manifest's permissions (`--allowedTools`, `--disallowedTools`), our MCP servers from `--mcp-config` with `--strict-mcp-config`, reference folders from `--add-dir` plus deny rules for edits there.
- **Codex** (`packages/runtime/src/acp.ts`): the bundled `codex-acp` adapter speaks the Agent Client Protocol. One long-lived process; `session/new`, `session/prompt`, `session/cancel`, `session/close`. Permission requests are answered from the manifest without asking the person.
- **OpenCode** (same `acp.ts`): the unmodified `opencode acp`, MIT. Modes `build` (edit) and `plan` (read-only) through `session/set_mode`; `plan` blocks edits but not shell commands. Any new place that builds ACP transport options spreads `acpFields(engine, edit)` (`packages/runtime/src/transport.ts`) instead of reading `engine.transport`.

## Getting an engine ready

Settings → Engine walks the steps in order; `engineProblem` (`packages/ui/src/client.ts`) picks the first one left from the status check (`detectEngine` in `packages/shell/src/main/engine-status.ts`): the legal notice, install (the official installer), update when below `minVersion`, sign in (the tool's own login, in the browser), and a tiny test prompt (`engine-check.ts`). The app finds the tool through the login shell's `PATH` (`engine-command.ts`), then in the folders official installers use (`~/.local/bin`, `/opt/homebrew/bin`, `/usr/local/bin`, and `~/.opencode/bin` for OpenCode's installer); Codex runs from the copy bundled with the adapter. `~/.humanharness/engines.json` (`shared-config.ts`) keeps the accepted notice, the version and the last successful test, never credentials.

### OpenCode's setup

- **Sign in and out in Terminal.** `opencode auth login` and `logout` are interactive (a provider picker), so they are `setup.inTerminal`. The app copies the command (`hh:copySetupCommand`, `install-help.ts`) and opens Terminal; it runs nothing there, and `hh:runSetup` refuses those steps. The onboarding shows a "Choose a provider in OpenCode" card (copy, open Terminal, check again, test a local model, the providers guide); the legal notice adds that the chosen provider's terms and privacy rules apply. Signing out from Settings › Engine also clears OpenCode's saved `verifiedAt`, so with no provider left the engine reads signed out until the test prompt runs again. Known gap: when that config write fails after the copy, the window shows a plain failure although the command is on the clipboard.
- **Status (`opencode-auth-list`, `engine-status.ts`).** Ready when `opencode auth list` lists at least one provider. OpenCode 1 prints text (ANSI codes stripped before counting); from 2.0 the app asks for `auth list --format json` and counts entries with a connection (`No authenticated integrations` is none). The app keeps only "at least one"; never a provider name, key, email or path. With no provider listed but a past successful test prompt (`verifiedAt`) the answer is "unknown", which counts as set up: that is how a person on a local model only (Ollama, set up in `opencode.json`, never listed by `auth`) gets ready, with "Test my local model". Known gap: when `--version` fails the app runs plain `auth list`, which OpenCode 2 may read as signed out.
- **Version.** `minVersion` is the placeholder `"0.0.0"` until a real OpenCode run sets it before release; 1.x and 2.x are both accepted.

## Models

- Claude's models are its aliases `haiku`, `sonnet` and `opus`, which always point at the latest version. Codex's list and efforts come from its adapter at `session/new` and are saved in `~/.humanharness/engines.json` for Settings › Modelos; until then only "Predeterminado del motor" is offered. An effort the engine doesn't offer is lowered to the closest one it does, or raised to its lowest when none is lower (`fitEffort`).
- Every value that reaches the command line or `CODEX_CONFIG` is checked first: model ids are letters, digits, `.`, `_`, `-` and brackets (plus `/` and `:`, which OpenCode's ids need, below) and never start with `-`; efforts come from a fixed list and caps are integers from 100k to 1M.
- OpenCode's models are `provider/model` ids (and Ollama tags such as `ollama/llama3.2:3b`), so `isModelId` accepts up to three `/`-separated parts and `:`, up to 128 characters. The list comes from OpenCode's `model` config option (the first 50 are kept); every tier uses OpenCode's default model until the person assigns one in Settings › Models.
- `CODEX_CONFIG` is written by the app from the task's profile, replacing any value in the app's own environment; it holds only `model`, `model_reasoning_effort` and `model_auto_compact_token_limit`. It is not a credential. A new profile restarts Codex's process.
- OpenCode (`profile: "config-option"`) gets no `CODEX_CONFIG` and is never restarted for a profile: before a turn the transport calls `session/set_config_option` with `model`, then with the effort option (id `reasoning_effort` or `effort`, or category `thought_level`) when OpenCode offers that exact value. A model or effort OpenCode refuses (`-32602`) is `model-unavailable`, and the usual fallback goes one tier down. A profile without a model after one with a model starts a fresh process, so a session never runs on a model the profile didn't ask for. The context cap is not sent: OpenCode compacts on its own; Settings still shows it. Known gap: a resumed session with a no-model profile runs the model the session was restored with, not OpenCode's default.

## Compliance

- Only the official tools, unmodified.
- The app never reads `~/.claude`, `~/.codex`, `~/.gemini`, `~/.config/opencode` or `~/.local/share/opencode`, and never adds or removes authentication environment variables. For OpenCode it never sets a key in the environment, writes `opencode.json` or passes `--provider`; it runs only `--version`, `auth list`, `auth login`, `auth logout`, `upgrade` and `acp`.
- Those folders and `~/.opencode` are protected paths in `validate.ts`: a harness folder can be neither inside nor above them. So `~/.local`, `~/.local/share` and `~/.config` are refused as harness folders for every engine (a saved folder there is re-checked at load and sends the person back to setup).
- `claude auth status --json` prints the account's email: the app reads only `loggedIn` from it.

## Cost (OpenCode)

- OpenCode's `usage_update` carries `cost` in USD, the session's running total. The transport keeps the total and the total at the last turn's end and turns the difference into the turn's `costUsd` on the `usage` event; it lands in `usage.jsonl` (`usage.costUsd`, real money, unlike Claude's `costEquivalentUsd`), for tasks and material stages. A non-USD currency, or an amount that is not a finite number ≥ 0, is ignored.
- A turn with no `usage_update` records no cost, not 0. OpenCode sends it only at the end of a prompt and only when it knows the model's context limit, so a local model without a known limit shows no cost at all; and none comes on `session/load`, so the first turn after a resume only sets the baseline. A failed turn leaves the baseline, so the next turn's cost includes it. The cost also depends on `session/prompt` answering with `usage` (spike A8, confirmed in the source only); this is checked against the real CLI before release. Child sessions are not counted (an OpenCode limit).
- Settings › Usage (`withSpent` in `usage-log.ts`), only for an engine with `reportsCost` and only while it is the chosen engine: "Spent in the last 30 days" sums `costUsd` over every line of the last 30 days, every profile together (one account pays). The row is absent when no line has a cost; a real 0 shows US$ 0.00. The plan text says the engine reports cost, not limits; there is no plans link.
- Claude and Codex never get `costUsd`, `spentUsd` or the row.
