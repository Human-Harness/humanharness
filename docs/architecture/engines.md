# Engines

An engine is an official AI command-line tool the person already uses. Human Harness drives that tool and never handles a key: Claude and Codex run on the person's subscription; OpenCode runs on whatever provider (an API key or a local model) the person set up in OpenCode itself.

## The registry

`packages/engines/src/index.ts` describes each engine: its legal status (`allowed`, `pending`, `excluded`) with the source and date, the plan it requires, where data goes, how to detect it (`detect.binary`, `versionArgs`, `minVersion`), its transport and its setup commands (`install`, `login`, `status`, `update`, `logout`). Optional facts only one engine sets so far: `transport.profile` (how a model profile reaches an ACP engine), `reportsCost` (the engine reports real money per turn), `setup.inTerminal` (steps the person runs in Terminal) and `setup.providersUrl`. `availableEngines` keeps the harness's engines that are allowed, plus the pending ones in development.

## Transports

- **Claude** (`packages/runtime/src/claude-cli.ts`): one `claude -p` process per turn with `--output-format stream-json`; the message goes in through stdin. A new session starts with `--session-id <uuid>`, later turns use `--resume`. Tools come from the manifest's permissions (`--allowedTools`, `--disallowedTools`), our MCP servers from `--mcp-config` with `--strict-mcp-config`. Settings files load from `--setting-sources project` only.
- **Reference folders on Claude** (`referenceSettingsArgs`). They get file access through one inline `--settings '{"permissions":{"additionalDirectories":[...]}}'`, plus `Edit`/`Write`/`MultiEdit` deny rules by absolute path in `--disallowedTools`; reads go through the bare `Read`, `Glob` and `Grep` allow rules. Without references there is no `--settings` (D0).
  - Never `--add-dir`: an `--add-dir` folder also loads its `.claude/skills`, `.claude/commands` and `.claude/agents` under the `project` source, and an agent there can carry a `permissionMode` nobody approved. The settings key "grants file access only and loads none of these" (code.claude.com/docs/en/skills and /permissions, "Additional directories grant file access, not configuration"). `--settings` sits above the project's own settings, and the trust gate on `additionalDirectories` applies to a project's `.claude/settings.json`, not to `--settings`.
  - Not checked live yet: that a reference folder's `.claude/agents` stay out of `claude -p` and its files stay readable this way.
- **Reference folders on Codex and OpenCode** (`acp.ts`). They are not sent to the engine at all: no `additionalDirectories` on `session/new`. They are only read roots in `decidePermission`, so a read or search request inside them is allowed and an edit there is refused. Whether the engine's own sandbox lets it read there is up to the engine. Since the core never names these folders to the engine, it gives the engine no reason to load their `.codex/`, `.agents/` or `.opencode/` (not checked live).
- **Linked folders on Claude** (`settingsArgs`, `docs/architecture/hatches.md`). A scope's linked folders join the reference folders in the same `--settings` `additionalDirectories`, built per turn from the turn's task scope; never `--add-dir`. A `read` folder gets the references' edit deny rules; a `write` folder gets `Edit`/`Write`/`MultiEdit` allow rules under its path and deny rules for its `.claude/**` and `.git/**`. A path no permission rule can spell (a comma, glob characters) makes `claudeArgs` throw; the picker refuses it first. Not checked live yet: `additionalDirectories` under `acceptEdits` with these deny rules, and whether the matcher treats `.Claude` or `.GIT` as the lower-case names on a case-insensitive volume.
- **Linked folders on Codex and OpenCode** (`acp.ts`). Only when `initialize` advertises `sessionCapabilities.additionalDirectories`: `write` folders go in `additionalDirectories` on `session/new` and every `session/load`, and a changed list reopens the session (`session/load` with the new list). `read` folders are never sent, only read roots. Write roots refuse edits under `.git`, `.codex`, `.agents`, `.opencode` and `.claude` (any case, through links). Without the capability nothing is sent and Scope settings says so. Codex treats every listed folder as a trusted project, so the folder's own `.codex/config.toml` and `.agents/skills` may load (not checked live); whether Codex asks permission for writes inside those folders at all is unverified.
- **Engine presets on Claude** (`settingsArgs`, `claudeArgs`; `docs/architecture/hatches.md`, H3). Only for a harness with `enginePresets` and a task whose scope's engine config the person approved. The preset's hooks and `permissions.allow/deny/ask` join the same single `--settings` as `additionalDirectories` (no `--settings` when all are empty). An `mcp__` allow rule passes only when it names one of the preset's own servers, `mcp__scope-<name>`. The preset's servers follow the core's in `--mcp-config`; `--plugin-dir <snapshot>/plugins/scope-<id>` (skills `/scope-<id>:<name>`) and `--agents <snapshot>/agents.json` follow `--settings`. The `global` base gives `--setting-sources user,project` and drops `--strict-mcp-config`; then the `--settings` also turns the folder's `.mcp.json` servers off (`enableAllProjectMcpServers: false`, `enabledMcpjsonServers: []`) and `--disallowedTools` adds the edit tools on `.mcp.json`. The harness's `--disallowedTools` always wins. Not checked live: `--plugin-dir` under `--setting-sources project` and `--strict-mcp-config` and on `--resume`; an agent's `tools` against `--disallowedTools`; which server wins under `global` when the person's own config names one `ui`, `data` or `scope-*`; `--agents` with a file needs Claude Code 2.1.281 or later, unchecked; that the `.mcp.json` switches above keep the folder's servers off (the CLI may merge arrays across setting sources).
- **Engine presets on Codex and OpenCode** (`acp.ts`). The preset's servers follow the core's in `mcpServers` on `session/new` and `session/load`, and they join the permission policy's server list for that turn, so their calls are approved without asking (on Claude the preset's rules apply instead). Codex only: the cleaned `codex.toml` is merged into `CODEX_CONFIG` (below). OpenCode gets the servers alone. A turn with another preset hash, or a preset dropped or added, restarts the process with a fresh session, as a new profile does. **The Codex limit:** `isolated` can't hold on Codex, since the app sets no `CODEX_HOME` and never reads `~/.codex`; the person's own Codex config and the project's `.codex/` always apply, and Scope settings says so.
- **Codex** (`packages/runtime/src/acp.ts`): the bundled `codex-acp` adapter speaks the Agent Client Protocol. One long-lived process; `session/new`, `session/prompt`, `session/cancel`, `session/close`. Permission requests are answered from the manifest without asking the person.
- **OpenCode** (same `acp.ts`): the unmodified `opencode acp`, MIT. Modes `build` (edit) and `plan` (read-only) through `session/set_mode`; `plan` blocks edits but not shell commands. Any new place that builds ACP transport options spreads `acpFields(engine, edit)` (`packages/runtime/src/transport.ts`) instead of reading `engine.transport`.
- **OpenCode's permissions.** OpenCode runs bash and webfetch without asking by default, so the harness's `exec` and `web` permissions would not apply. The registry's `transport.env` (`OPENCODE_ENV`, only OpenCode has one) reaches the process through `acpFields` → `TransportOptions.engineEnv`, set last over the inherited environment:
  - `OPENCODE_CONFIG_CONTENT={"permission":{"bash":"ask","edit":"ask","webfetch":"ask","websearch":"ask"}}` (inline config, OpenCode 1 and 2, above the person's global and project config);
  - `OPENCODE_PERMISSION` with the same map (OpenCode 1 merges it last over every `permission`; OpenCode 2 does not read it);
  - `OPENCODE_DISABLE_CLAUDE_CODE=1` (OpenCode does not read `~/.claude/CLAUDE.md` or `.claude/skills`, so they never reach the person's provider).

  Every bash, edit and web call then comes as `session/request_permission`, and `decidePermission` answers it from the manifest, as for Codex. Sources: `anomalyco/opencode` v1.19.4 `packages/opencode/src/config/config.ts:482-489,559-561` and `packages/opencode/src/effect/runtime-flags.ts:24,28`; `dev` (2.x) `packages/cli/src/server-process.ts:128-133` and `packages/core/src/config/normalize.ts:180`; `opencode.ai/docs/cli` (environment variables). Known gaps: a tool rule inside one of the person's own OpenCode agents (`agent.<name>.permission`) applies after these and can loosen them; OpenCode reports `websearch` as kind `other`, so `exec` (not `web`) decides it.

## Transports per slot

- Each `SessionSlot` has its own transport (`packages/runtime/src/workspace.ts`, `turn.md`).
- Slots never share an ACP adapter, even with the same profile. One slot's `session/cancel` or crash can't touch another.
- Claude needs nothing new. Each turn is already its own `claude -p` process.
- `slot.sleep()` closes an idle ACP adapter process (`AcpTransport.close()`) and keeps the session id. The next turn starts a new process and calls `session/load`. For Claude, `sleep()` does nothing.
- When `session/load` fails, `openSession` falls back to `session/new`. Only an expired login is an error. The new session is reported through `onSession`. The earlier conversation is then lost. In board mode the task shows the system line "Couldn't resume the earlier conversation; started a new one." (a live `task-notice` of kind `resume-failed`, not saved in the chat; `parallel.md`); a plain harness tells nothing yet.
- `AcpTransport` sets its event sink only after `openSession`. A history that `session/load` replays never reaches the window or the turn's `edits`. Keep that order.

### Spike facts (PT-S1…S5)

Source: `docs/spikes/2026-10-28-parallel-tasks.md`.

- **PT-S1.** Two `claude -p` turns run at once in one folder. Each keeps its own session.
- **PT-S1.** Claude names an edited file by its absolute real path. A folder opened through a link (`/tmp` on macOS) matches only after `realpath`. The ledger accepts both forms.
- **PT-S2.** In `-p`, a tool call that needs approval is denied at once. The turn goes on to its end. Read-only shell commands run without approval.
- **PT-S3.** Two Codex adapters run at once, in one folder or two.
- **PT-S3.** A Codex edit names its path only in `content[].diff.path`. Its `locations` is empty. The path has the form of the `cwd` Codex was given, not the real path.
- **PT-S3.** Codex often writes files through the shell. A shell write names no path. Those changes count as shared, never as an error.
- **PT-S3.** One adapter uses about 0.3 GB of memory. `initialize` answers 2.2–2.6 s after spawn.
- **PT-S4.** A Codex session survives its adapter process. A new process's `session/load` resumes it in about 2–3 s.

### Spike limits

- **PT-S4** was tested on the happy path only: three short runs. A long idle, a large session and a failed load were not tested.
- **PT-S5** did not run: OpenCode was not installed. Two OpenCode processes at once are unverified. Until a spike shows it works, `engineHold` holds every engine but Claude and Codex, OpenCode included, at one session: one turn at a time, other lanes' processes put to sleep first (`parallel.md`).
- **Codex edit paths** come only from `content[].diff.path`. Shell writes are unnamed, so with Codex `edits` misses many changes.
- The spike ran the adapter through `npx`, not the copy the app bundles. Its timings and memory figures were read from stdout and not saved.

## Getting an engine ready

Settings → Engine walks the steps in order; `engineProblem` (`packages/ui/src/client.ts`) picks the first one left from the status check (`detectEngine` in `packages/shell/src/main/engine-status.ts`): the legal notice, install (the official installer), update when below `minVersion`, sign in (the tool's own login, in the browser), and a tiny test prompt (`engine-check.ts`). The app finds the tool through the login shell's `PATH` (`engine-command.ts`), then in the folders official installers use (`~/.local/bin`, `/opt/homebrew/bin`, `/usr/local/bin`, and `~/.opencode/bin` for OpenCode's installer, searched only for `opencode`); Codex runs from the copy bundled with the adapter. `~/.humanharness/engines.json` (`shared-config.ts`) keeps the accepted notice, the version and the last successful test, never credentials.

The legal notice's texts (its title, content and the accept checkbox) are `legal.engine.*` keys in the core `en.json`. They are never translated and always render in English, followed by "Legal texts are shown in English." when the screen is in another language (`docs/architecture/language.md`). The `engine.terms` and `engine.privacy` link labels stay translatable: they name a document.

### OpenCode's setup

- **Sign in and out in Terminal.** `opencode auth login` and `logout` are interactive (a provider picker), so they are `setup.inTerminal`. The app copies the command (`hh:copySetupCommand`, `install-help.ts`) and opens Terminal; it runs nothing there, and `hh:runSetup` refuses those steps. The onboarding shows a "Choose a provider in OpenCode" card (copy, open Terminal, check again, test a local model, the providers guide); the legal notice adds that the chosen provider's terms and privacy rules apply. Signing out from Settings › Engine also clears OpenCode's saved `verifiedAt`, so with no provider left the engine reads signed out until the test prompt runs again. When the command is copied but Terminal does not open, the window says the command is copied and to open Terminal by hand. Known gap: when the `verifiedAt` config write fails after the copy, the window shows a plain failure although the command is on the clipboard.
- **Status (`opencode-auth-list`, `engine-status.ts`).** Ready when `opencode auth list` lists at least one provider. OpenCode 1 prints text (ANSI codes stripped before counting); from 2.0 the app asks for `auth list --format json` and counts entries with a connection (`No authenticated integrations` is none). The app keeps only "at least one"; never a provider name, key, email or path. With no provider listed but a past successful test prompt (`verifiedAt`) the answer is "unknown", which counts as set up: that is how a person on a local model only (Ollama, set up in `opencode.json`, never listed by `auth`) gets ready, with "Test my local model". Known gap: when `--version` fails the app runs plain `auth list`, which OpenCode 2 may read as signed out.
- **Version.** `minVersion` is the placeholder `"0.0.0"` until a real OpenCode run sets it before release; 1.x and 2.x are both accepted.

## Models

- Claude's models are its aliases `haiku`, `sonnet` and `opus`, which always point at the latest version. Codex's list and efforts come from its adapter at `session/new` and are saved in `~/.humanharness/engines.json` for Settings › Modelos; until then only "Predeterminado del motor" is offered. An effort the engine doesn't offer is lowered to the closest one it does, or raised to its lowest when none is lower (`fitEffort`).
- Every value that reaches the command line or `CODEX_CONFIG` is checked first: model ids are letters, digits, `.`, `_`, `-` and brackets (plus `/` and `:`, which OpenCode's ids need, below) and never start with `-`; efforts come from a fixed list and caps are integers from 100k to 1M.
- OpenCode's models are `provider/model` ids (and Ollama tags such as `ollama/llama3.2:3b`), so `isModelId` accepts up to three `/`-separated parts and `:`, up to 128 characters. The list comes from OpenCode's `model` config option (Settings keeps the first 50; a profile's model is checked against every model offered); every tier uses OpenCode's default model until the person assigns one in Settings › Models.
- `CODEX_CONFIG` is written by the app from the task's profile, replacing any value in the app's own environment; it holds only `model`, `model_reasoning_effort` and `model_auto_compact_token_limit`. It is not a credential. A new profile restarts Codex's process. With an approved engine preset (`hatches.md`, H3) the preset's cleaned `codex.toml` is merged deep into it (`mergeCodex`): the core's keys win at every depth, and a preset `model`, `model_reasoning_effort` or `model_auto_compact_token_limit` is refused. Without a preset it is exactly as above (D0).
- OpenCode (`profile: "config-option"`) gets no `CODEX_CONFIG` and is never restarted for a profile: before a turn the transport calls `session/set_config_option` with `model`, then with the effort option (id `reasoning_effort` or `effort`, or category `thought_level`) when OpenCode offers that exact value. A model or effort OpenCode refuses (`-32602`) is `model-unavailable`, and the usual fallback goes one tier down; that fallback happens only on a task's first turn. A model OpenCode stops offering in the middle of a task (a `config_option_update` without it) gives `model-unavailable` on the task's next turn, with no fallback. Known gap: the efforts saved for Settings (`onModels` → `engines.json`, `packages/shell/src/main/index.ts`) are the ones OpenCode offered for the last model used, since OpenCode offers efforts per model (its variants); another model may offer others. A profile without a model after one with a model starts a fresh process, so a session never runs on a model the profile didn't ask for. The context cap is not sent: OpenCode compacts on its own; Settings still shows it. Known gap: a resumed session with a no-model profile runs the model the session was restored with, not OpenCode's default.

## Compliance

- Only the official tools, unmodified.
- The app never reads `~/.claude`, `~/.codex`, `~/.gemini`, `~/.config/opencode` or `~/.local/share/opencode`, and never adds or removes authentication environment variables. For OpenCode it never sets a key in the environment, writes `opencode.json` or passes `--provider`; the only environment it sets is the permission config and `OPENCODE_DISABLE_CLAUDE_CODE` above; it runs only `--version`, `auth list`, `auth login`, `auth logout`, `upgrade` and `acp`.
- Those folders and `~/.opencode` are protected paths in `validate.ts`: a harness folder can be neither inside nor above them. So `~/.local`, `~/.local/share` and `~/.config` are refused as harness folders for every engine (a saved folder there is re-checked at load and sends the person back to setup).
- `claude auth status --json` prints the account's email: the app reads only `loggedIn` from it.

## Cost (OpenCode)

- OpenCode's `usage_update` carries `cost` in USD, the session's running total. The transport keeps the total and the total at the last turn's end and turns the difference into the turn's `costUsd` on the `usage` event; it lands in `usage.jsonl` (`usage.costUsd`, real money, unlike Claude's `costEquivalentUsd`), for tasks and material stages. A non-USD currency, an amount that is not a finite number ≥ 0, or a `usage_update` whose `sessionId` is not the open session's, is ignored. The summary checks again: `spentUsd` adds only logged costs that are finite and ≥ 0.
- A turn with no `usage_update` records no cost, not 0. OpenCode sends it only at the end of a prompt and only when it knows the model's context limit, so a local model without a known limit shows no cost at all; and none comes on `session/load`, so the first turn after a resume only sets the baseline. A changed list of linked folders reopens the session (`hatches.md`), so the turn after it records no cost either (known gap). A failed turn leaves the baseline, so the next turn's cost includes it. The cost does not depend on `session/prompt` answering with `usage` (spike A8): without it the `usage` event still carries `costUsd`, with 0 tokens. The turn's cost is taken only where it is emitted, so the baseline never moves without a recorded cost. Codex's `usage` event is unchanged (D0). Child sessions are not counted (an OpenCode limit).
- Settings › Usage (`withSpent` in `usage-log.ts`), only for an engine with `reportsCost` and only while it is the chosen engine: "Spent in the last 30 days" sums `costUsd` over every line of the last 30 days, every profile together (one account pays). The row is absent when no line has a cost; a real 0 shows US$ 0.00. The plan text says the engine reports cost, not limits; there is no plans link.
- Claude and Codex never get `costUsd`, `spentUsd` or the row.
