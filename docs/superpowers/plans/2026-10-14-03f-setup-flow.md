### Task 1: Mock engine and mock model (shell)

**Files:** `packages/shell/src/main/test-hooks.ts`, `packages/shell/src/main/index.ts`, `packages/ui/src/client.ts` (`EngineOption.mock?: boolean`), shell tests next to the existing test-hooks tests.

- Add `mock?: boolean` to `EngineOption` (UI client type), documented as "a faked engine in `humanharness dev --mock`".
- In `test-hooks.ts` add pure helpers, unit-tested:
  - `mockEngineText(language)`: the localized presentation of spec §4 (name "Motor de prueba"/"Test engine", provider "Human Harness", requires, dataLocation, trainsOnData as `{es,en}` texts).
  - `MOCK_MODEL = "mock"` and `mockModels(language)`: `[{ id: "mock", name: "Modelo de prueba" | "Test model" }]`.
- In `index.ts` `appState()`: when `hooks.mock` and the engine has a fake, send the mock presentation: no logo, no install command, `reportsLimits: false`, `mock: true`. Language is the saved one, else `app.getLocale()` starting with "es" → es, else the harness's first language.
- `modelsView()`: in mock mode, for a faked engine, offered models are `mockModels(lang)` (efforts unchanged), and each tier's default spec has `model: "mock"` (effort and cap kept).
- Engine status (line ~565): in mock mode a faked engine reports `noticeAccepted: true`. Plain fake engines (no `hooks.mock`) keep the real notice.
- Tests: helpers; that `offeredEngines`/status behaviour is unchanged without `mock`.

### Task 3: Setup flow screen (ui)

**Files:** new `packages/ui/src/SetupFlow.tsx`, `packages/ui/src/FolderStep.tsx` (optional `submitLabel` and `welcome?: boolean`), styles, i18n, new `packages/ui/test/setup-flow.test.tsx`.

- `SetupFlow({ client, state, onChange, onCancel, onStart })`, spec §2: top bar (title "Configurar {{name}}", mock badge), stepper with checks, step body, footer.
- Step 1 uses `FolderStep` with submit label "Siguiente" (it saves folder and language; when `state.config.folder` becomes set, advance). Skip step 1 when a folder is already saved. Footer: Cancelar (→ `onCancel`).
- Step 2 uses `EngineTab` with `setup` and `onSelection`. Siguiente enabled only when the selected engine is ready; it saves `engineId` if it differs, then shows step 3. Footer: Atrás (to step 1 only if step 1 was shown, else Cancelar).
- In mock mode, step 2 shows the caption of spec §4 under the heading.
- Step 3 "Todo listo": check, folder (display path), engine name (plus "Modelo de prueba" for a mock engine), hint, big "Iniciar {{name}}" (`hh-primary hh-start`) → `onStart`.
- Tests: fresh state walks folder → engine → done → onStart; configured folder skips step 1; Siguiente disabled until ready; Cancelar calls onCancel.
