# Docs that check themselves — design

Date: 2026-11-13
Status: written, waiting for Marco's review
Source: the herdr comparison (https://claude.ai/artifact/9rsD7WqQSYDPyPKQqyGci8), improvement 6. herdr generates its reference tables from code and fails CI when a public name has no doc.

## 1. Goal

An agent that reads `docs/architecture` finds every way the window talks to main, and every key of `config.json`.

- The window and main talk over 217 IPC channels, listed in `packages/protocol/src/channels.ts` (`Invoke` and `Push`).
- Today 97 of them are named in no doc. Examples: `hh:pauseTask`, `hh:materialAdd`, `hh:getUsage`.
- `config.json` has 15 top-level keys (`AppConfig` in `packages/protocol/src/views.ts`). Only `models` and `profile` are named as `` `config.json` → `key` `` in a doc.
- An agent that finds no doc reads `shell/src/main/index.ts` instead. That file is 3,800 lines, so the agent spends context and can still miss things.

This spec adds:
- a generated table of every channel and config key;
- a test that a new channel or key cannot land without a doc;
- a list of today's gaps that only shrinks.

It changes no behaviour.

## 2. What is checked

| Surface | Source | Count today |
|---|---|---|
| Invoke channels | `interface Invoke` in `packages/protocol/src/channels.ts` | 183 |
| Push channels | `interface Push` in the same file | 35 |
| Config keys | the top-level keys of `interface AppConfig` in `packages/protocol/src/views.ts` | 15 |

`hh:scopes` is in both tables (an invoke and a push of the same name), so there are 217 distinct channel names. The check works on names: one doc mention covers both.

**Not checked.**
- `hh.d.ts`, the mod API. The minimal-core spec (§7, Docs) already checks it against the generated `AGENTS.md`.
- The plugin and tool realms (`hh-plugin:rpc`, `hh-tools:rpc`). They have their own preloads, and the plugin runtime is deleted in minimal-core step 6.
- A harness's own settings fields. Each harness declares them, so they are not part of the core.
- Nested config keys such as `models.pinnedTokens`. They stay in their feature's doc, unchecked.

## 3. What counts as documented

The docs searched are every `docs/architecture/*.md` except `contract.md` (§4), and every `packages/mods/*/README.md`. The minimal-core spec moves each mod's feature doc to that README, so the check keeps working as features move.

- **A channel** is documented when its name appears in backticks: `` `hh:pauseTask` ``.
- **A config key** is documented when it appears as `` `config.json` → `key` ``, the form the docs already use (`settings.md`: "`config.json` → `models`").
  - A bare `` `language` `` does not count. That word appears in many docs that are not about the config key.
  - `->` is accepted in place of `→`.

A name inside a code block counts too. The check is a text search, not a Markdown parse.

## 4. The generated table

The file is `docs/architecture/contract.md`. Nobody edits it by hand.

- **The script.** `pnpm docs:gen` (root `package.json`) runs `packages/protocol/scripts/gen-contract-docs.ts`.
  - It reads the two interfaces and `AppConfig` with the same regex reader that `packages/protocol/test/channels.test.ts` uses (`tableKeys`). That reader moves to `packages/protocol/test/contract-keys.ts`, so the existing test, the new test and the script all share it.
  - It writes the file and nothing else.
- **The content.**
  - A header line: "Generated by `pnpm docs:gen` from `channels.ts` and `AppConfig`. Do not edit."
  - Three tables: Invoke channels, Push channels, `config.json` keys.
  - Each table has two columns: the name, and where it is documented. The second column lists the docs that name it (§3), as relative links. A name in the exception list (§5) shows "—".
  - Rows are sorted by name, so a new channel is a one-line diff.
- **Size.** About 235 rows (183 + 35 + 15). That is well under the 32 KB target of the file-size spec.

## 5. The test and the exception list

The test is `packages/protocol/test/docs-coverage.test.ts`. It sits next to `channels.test.ts` and `boundary.test.ts`, the other repo-wide rules.

- **The exception list** is `packages/protocol/test/undocumented.json`. It holds a sorted array of names: today's 97 channels. It sits next to the test, as the file-size spec does with its baseline.
- **The test fails when:**
  1. `contract.md` differs from what the script would write. Message: "docs/architecture/contract.md is out of date: run `pnpm docs:gen`."
  2. A channel or config key is not documented (§3) and not in the list. Message: "`hh:pauseTask` is in channels.ts but no doc names it. Add it to its feature's doc in docs/architecture (or the mod's README)."
  3. A name in the list no longer exists, or is now documented. Message: "`hh:pauseTask` is documented now (or gone): remove it from undocumented.json."
- **The list only shrinks.**
  - Check 3 forces the removal of an entry once its gap is closed.
  - A new name never goes in the list. Adding one is a review flag: the PR needs a line saying why.
  - Nothing rewrites the list automatically.

## 6. Starting state

The first PR does three things:
- moves `tableKeys` to `contract-keys.ts`, with no behaviour change;
- adds the script, the test, `contract.md`, and `undocumented.json` with today's undocumented channels;
- documents the 13 config keys no doc names yet. Each gets one line in a new section "`config.json`" of `docs/architecture/settings.md`, in the `` `config.json` → `key` `` form, saying what the key holds and which Settings tab writes it. The two keys that are already named elsewhere get a line there as well, for a full list in one place;

No config key goes into the exception list, so it starts with channels only.

## 7. Dependencies and order

- **The task-manager split.** The queue placed this item after the file-size split of `task-manager.ts`. The check reads `channels.ts`, `views.ts` and the docs; it never reads `task-manager.ts`. It does not wait for the split.
- **Work in flight.** `ark/mods-0c1-mod-kit` may add channels. If 0c1 lands first, this PR's starting list includes any of its channels that no doc names. If this lands first, 0c1 rebases, runs `pnpm docs:gen`, and documents its new channels: the exception list is closed to them.
- **Minimal core.** When a step moves a feature into a mod and deletes its channels, check 3 asks for their exception entries to go. When a step moves a feature's doc into `packages/mods/<id>/README.md`, the check keeps finding it (§3).

## 8. Testing

- The test itself runs in the normal `pnpm test`.
- The script and the test share one generator function (`renderContract()` in the script, imported by the test), so check 1 compares the file against the same code that writes it.
- Unit tests of the matcher, with small inline fixtures:
  - a channel named in backticks counts; a channel only in plain text does not;
  - `` `config.json` → `key` `` and `` `config.json` -> `key` `` count; a bare `` `key` `` does not;
  - `contract.md` itself is never a source of "documented".
