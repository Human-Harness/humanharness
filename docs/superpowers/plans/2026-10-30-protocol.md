# Protocol Implementation Plan (replaceable parts, plan 2)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The UI/core contract leaves the UI: a new `@humanharness/protocol` package holds the client interfaces, the view models, the shared pure helpers and a typed IPC channel table. The shell's main and preload import `protocol` instead of `@humanharness/ui`, `ui/src` imports no core package, and a mistyped channel name fails at compile time.

**Architecture:**
- **`packages/protocol`** (new, renderer-safe: no Node, no Electron, no React). `src/client.ts` holds the `*Client` interfaces; `src/views.ts` the view models and every other contract type; `src/shared.ts` the pure helpers and constants both sides use; `src/events.ts` re-exports the engine events; `src/data-change.ts` keeps `hearsDataChange` in its own module for the preload; `src/channels.ts` holds the channel table; `src/index.ts` re-exports all but `channels.ts` and `data-change.ts` (subpaths `@humanharness/protocol/channels`, `@humanharness/protocol/data-change`).
- **`ui/src/client.ts` becomes a re-export** of `@humanharness/protocol` plus the helpers only views use (`partsOf`, `engineProblem`). Every view and every `ui` test keeps importing `./client` and does not change.
- **The channel table** (`channels.ts`) has two type maps: `Invoke` (channel → the wire function: arguments → result) and `Push` (channel → payload). The preload calls `invoke(channel, …args)` (typed arguments and result); main registers with `handle(channel, fn)` / `handleAll(map)` (typed channel name). Channel names do not change.
- **Tests:** `packages/protocol/test/channels.test.ts` scans the shell's sources: every channel in the table is handled in main and used by the preload, and every `"hh:…"` literal in main and the preload is in the table. `packages/protocol/test/boundary.test.ts` enforces §5.5's import rules.

**Tech Stack:** TypeScript (tsc 7, `moduleResolution: bundler`), pnpm via corepack, Vitest, Electron 44 + electron-vite 5 (build check), Playwright e2e.

Spec: `docs/superpowers/specs/2026-10-29-replaceable-parts-design.md`, §5 (part 2), §8 (boundary test), §12, D2, D6. "§" and "D" numbers below refer to it.

## Deviations from the spec (decided while planning; tell Marco)

1. **`protocol` also imports types from `workspace` and `i18n`, and re-exports `@humanharness/workspace/subjects` (§5.4 says `harness-sdk` and `engines` types only).** The contract today names workspace types (`DataChange`, `FileDiffView`, `TimelineEntry`, `SyncStatus`…) and `GeneratedStrings`; moving those types up into `protocol` would make `workspace` import `protocol`, against §3's arrows. The history's commit subjects (`NOTE`, `RESTORE_POINT`…) are plain constants with no imports that both sides read. So: `import type` only from `engines`, `workspace`, `i18n`; the one value import is `@humanharness/workspace/subjects`. The boundary test enforces exactly that.
2. **The renderer still imports `@humanharness/ui` (§5.5 says "`shell/` has no import of `@humanharness/ui`").** `shell/src/renderer` is the UI's host: it mounts the harness's screen and loads `ui/styles.css`. The rule applies to `shell/src/main` and `shell/src/preload` (and the shell's tests); `shell/package.json` keeps the `ui` dependency for the renderer.
3. **`ui` may import `@humanharness/i18n`** (§8 lists `protocol` and `harness-sdk` only). `HarnessApp` builds its i18next instance with `createI18n` and the language picker uses `i18n/translate`: the renderer runs that code itself. §5.5's list (`runtime`, `engines`, `workspace`) is what the test forbids.
4. **The shared helpers are what the shell imports today, which includes `timeAgo`, `addText` and `laterTasks`** (§5.1 lists them as UI-only). §5.1's own rule ("the exact list is whatever `shell/src/main` and `shell/src/preload` import") wins: `go-back.ts` and `chat-log.ts` use them. Only `partsOf` and `engineProblem` (with `EngineProblem`) stay in `ui`.
5. **Main checks channel names, not argument and result types.** Main's handlers take `unknown` arguments on purpose (renderer input is untrusted and validated) and many return `Promise<unknown>`; the preload is where arguments and results get their types. `handle`, `handleFrom`, `handleAll` and the push senders accept only table channels.
6. **The plugin and tool realms' channels (`hh-plugin:rpc`, `hh-tools:rpc`) stay out of the table.** They serve sandboxed windows with their own preloads and their own method validation (`plugin-host.ts`, `tool-host.ts`); `plugin-broker.ts` and `plugin-secrets.ts` are not touched.
7. **§12 — `runtime` keeps re-exporting `Transport`, `Event` and the rest of the contract.** 55 files outside `runtime` import contract names through `@humanharness/runtime`; moving them is churn with no behaviour change, and `ui` no longer needs `runtime` at all. Revisit if a later plan touches those files anyway.
8. **The `ui` tests stay in `ui/test`** even when they cover a helper now in `protocol` (`client.test.ts`): they import `../src/client`, which re-exports it, so D2 holds with no edit.

### Task 4: The channel table and the preload's typed `invoke`

- [ ] **Step 1: Write `channels.ts`'s helpers and the maps' shape**

```ts
// The IPC channels between the window's preload and main (replaceable parts §5.3, D6): a renamed or mistyped
// channel fails at compile time. `Invoke`: what the preload asks with ipcRenderer.invoke — the wire arguments and
// what main answers. `Push`: what main sends with webContents.send — the payload. Channel names never change here.
// The plugin and tool realms (hh-plugin:rpc, hh-tools:rpc) have their own preloads and are not in this table.
import type { … } from "./views";
import type { … } from "./client";

export interface Invoke {
  "hh:getState": () => AppState;
  "hh:pickFolder": (defaultPath?: string) => FolderPick;
  // … one entry per channel
}

export interface Push {
  "hh:event": Event;
  "hh:setupOutput": SetupOutput;
  // … one entry per channel
}

export type InvokeChannel = keyof Invoke;
export type PushChannel = keyof Push;
export type InvokeArgs<C extends InvokeChannel> = Parameters<Invoke[C]>;
/** What main answers, unwrapped: `invoke` always returns a promise. */
export type InvokeResult<C extends InvokeChannel> = Awaited<ReturnType<Invoke[C]>>;
```

- [ ] **Step 2: Fill both maps from the preload**

List every channel: `grep -ohE '"hh:[A-Za-z]+"' packages/shell/src/preload/*.ts | sort -u` (about 199 today, including channels named through constants: also grep main for `as const` channel arrays such as `CONTEXT_CHANNELS`, `REVIEW_CHANNELS`, `FILE_CHANNELS`, `LANGUAGE_CHANNELS`, `GO_BACK_CHANNELS`, `CONNECTIONS_TEST_CHANNEL`, and the `CHANGED` constant in `engine-config/engine-ipc.ts`).

For each channel:
- **Invoke** (used with `ipcRenderer.invoke`, `fileInvoke`, `askContext`, `ask`): the entry's parameters are exactly what the preload passes on the wire; its result is what the preload hands on. Where a client method passes its arguments straight through and returns main's answer unchanged, reuse the method's type: `"hh:restore": HarnessClient["restore"]`, `"hh:contextGet": ContextClient["get"]`, and unwrap any `Promise` in the result (`InvokeResult` awaits it, so `HarnessClient["restore"]` works as is). Where the preload transforms (e.g. `send` passes `options ?? {}`; `askContext` turns a rejection into `{ ok: false, reason: "failed" }`; `backendClient`'s `plainError`), write the wire signature and use `unknown` for a result the preload validates before use.
- **Push** (used with `subscribe` or `ipcRenderer.on`): the payload type the listener receives; `unknown` where the preload validates it (`hh:context`, `hh:backendEvent`, `hh:backendStateChange`, `hh:fileCommits`).

Every entry gets no comment unless the wire shape differs from the client method it serves (then one line saying how).

- [ ] **Step 3: The preload's typed helpers**

`packages/shell/src/preload/ipc.ts`:

```ts
import type { InvokeArgs, InvokeChannel, InvokeResult, Push, PushChannel } from "@humanharness/protocol/channels";
import { ipcRenderer } from "electron";

/** `ipcRenderer.invoke` on a table channel (replaceable parts §5.3): typed arguments and answer. */
export function invoke<C extends InvokeChannel>(channel: C, ...args: InvokeArgs<C>): Promise<InvokeResult<C>> {
  return ipcRenderer.invoke(channel, ...args);
}

/** Listens on a table push channel; returns the unsubscribe. */
export function subscribe<C extends PushChannel>(channel: C, listener: (value: Push[C]) => void): () => void {
  const handler = (_e: unknown, value: Push[C]) => listener(value);
  ipcRenderer.on(channel, handler);
  return () => ipcRenderer.removeListener(channel, handler);
}
```

function sources(dir: string): string[] {

/** Every "hh:…" string literal in a folder's sources (comments use backticks, so they don't count). */
function literals(dir: string): Set<string> {
  const found = new Set<string>();
  for (const file of sources(dir)) for (const m of fs.readFileSync(file, "utf8").matchAll(/"(hh:[A-Za-z]+)"/g)) found.add(m[1]);

/** The keys of one interface in channels.ts. */
function tableKeys(name: "Invoke" | "Push"): Set<string> {

```ts
import fs from "node:fs";
import path from "node:path";
import { fileURLToPath } from "node:url";
import { describe, expect, it } from "vitest";

const packages = path.resolve(path.dirname(fileURLToPath(import.meta.url)), "../..");

function sources(dir: string): string[] {
  return fs.readdirSync(dir, { withFileTypes: true }).flatMap((d) => {
    const p = path.join(dir, d.name);
    if (d.isDirectory()) return d.name === "node_modules" ? [] : sources(p);
    return /\.tsx?$/.test(d.name) ? [p] : [];
  });
}

interface Import {
  file: string;
  spec: string;
  typeOnly: boolean;
}

/** Every static import and re-export with a `from` (multi-line ones included). */
function imports(dir: string): Import[] {
  return sources(dir).flatMap((file) =>
    [...fs.readFileSync(file, "utf8").matchAll(/^(import|export)\s+(type\s+)?[^;]*?\sfrom\s+"([^"]+)"/gms)].map((m) => ({
      file: path.relative(packages, file),
      spec: m[3],
      typeOnly: m[2] !== undefined,
    })),
  );
}

const offenders = (list: Import[], bad: (i: Import) => boolean) => list.filter(bad).map((i) => `${i.file} → ${i.spec}`);

describe("import boundaries (replaceable parts §5.5, §8)", () => {
  it("ui/src imports no core package", () => {
    const core = /^@humanharness\/(runtime|engines|workspace|material|blocks|shell)(\/|$)/;
    expect(offenders(imports(path.join(packages, "ui/src")), (i) => core.test(i.spec))).toEqual([]);
  });

  it("the shell's main and preload do not import ui", () => {
    const list = [...imports(path.join(packages, "shell/src/main")), ...imports(path.join(packages, "shell/src/preload"))];
    expect(offenders(list, (i) => /^@humanharness\/ui(\/|$)/.test(i.spec))).toEqual([]);
  });

  it("protocol imports harness-sdk, and only types from engines, workspace and i18n (plus the history subjects)", () => {
    const allowed = (i: Import) =>
      !i.spec.startsWith("@humanharness/") ||
      /^@humanharness\/harness-sdk(\/|$)/.test(i.spec) ||
      i.spec === "@humanharness/workspace/subjects" ||
      (i.typeOnly && /^@humanharness\/(engines|workspace|i18n)$/.test(i.spec));
    expect(offenders(imports(path.join(packages, "protocol/src")), (i) => !allowed(i))).toEqual([]);
  });

  it("protocol is renderer-safe: no Node, Electron or React", () => {
    expect(offenders(imports(path.join(packages, "protocol/src")), (i) => /^(node:|electron$|react)/.test(i.spec))).toEqual([]);
  });
});
```

Note: an `export type { … } from "x"` and an `import type { … } from "x"` match `typeOnly`; an `import { type A } from "x"` does not. If the moved code uses the inline `type` form for an engines/workspace/i18n import, change it to `import type` (an import-line edit in `src`, not a test).
